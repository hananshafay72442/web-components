# Room component

Self-contained room feature for the group project: create a room, share a
link, join it, and see the member count update live.

- **Backend:** Flask + `flask-sock` (plain WebSockets, no socket.io)
- **Frontend:** React + React Router
- **Storage:** in memory (no database yet, as agreed)
- **No CSS:** class names are kept only as hooks for the host app's styles

## Files

```
room_component/
  requirements.txt
  backend/
    __init__.py      <- import ONE file: register_room_component(app)
    store.py         rooms + member IDs (no Flask, no sockets)
    hub.py           broadcasts updates to open sockets
    routes.py        HTTP: create / read / join
    websocket.py     WS:  /ws/room/<token>
  frontend/
    index.js         <- import ONE file: RoomModule, ShareRoomButton, ...
    RoomModule.jsx   routes: index = create page, ":token" = room page
    CreateRoomPage.jsx
    RoomPage.jsx
    ShareRoomButton.jsx
    api.js           the only HTTP call left (create room)
    memberId.js      per-browser random ID (localStorage)
    useRoom.js       WebSocket connect + join + live updates
```

## Backend merge

```bash
pip install -r room_component/requirements.txt
```

```python
from flask import Flask
from room_component.backend import register_room_component

app = Flask(__name__)
register_room_component(app)   # adds /api/room... and /ws/room/<token>
```

Optional: `register_room_component(app, url_prefix="/rooms-api", ws_path="/rooms-ws")`
if the host app already uses `/api` or `/ws`. Change `API_BASE` in
`frontend/api.js` and `WS_PATH` in `frontend/useRoom.js` to match.

Endpoints added:

| Method | Path                     | Purpose                              |
| ------ | ------------------------ | ------------------------------------ |
| POST   | `/api/room`              | create a room                        |
| GET    | `/api/room/<token>`      | read a room                          |
| POST   | `/api/room/<token>/join` | join over HTTP (optional)            |
| WS     | `/ws/room/<token>`       | join + receive live room updates     |

## Frontend merge

Copy `room_component/frontend` next to your React source and import the entry
file:

```jsx
import { Route } from 'react-router-dom'
import { RoomModule, ShareRoomButton } from './room_component/frontend'

// Create page at /rooms, room page at /rooms/<token>:
<Route path="/rooms/*" element={<RoomModule />} />

// Optional, inside your navbar; it only renders on room pages:
<ShareRoomButton />
```

The component expects `/api` and `/ws` on the same origin as the page. For
Vite dev, proxy both to Flask:

```js
// vite.config.js
server: {
  proxy: {
    '/api': 'http://localhost:5000',
    '/ws': { target: 'ws://localhost:5000', ws: true },
  },
},
```

## How joining works (no sockets knowledge needed)

1. The browser gets a random `memberId` once and keeps it in `localStorage`.
2. It opens a WebSocket to `/ws/room/<token>` and sends
   `{"type": "join", "memberId": "..."}`.
3. Flask adds the ID to that room's set (a set, so re-joining is a no-op).
4. Flask broadcasts `{"type": "room", "room": {...}}` to every socket watching
   that room, including the one that just joined.
5. Each page replaces its room state with the message, so the count updates
   instantly — no polling.

If the connection drops, the page reconnects after 2 seconds. Permanent
errors (unknown room, bad message) close with codes `4004` / `4400`, which the
page does not retry.

## Known limits (fine for this project)

- Rooms reset when the server restarts (in-memory).
- Member count only grows: closing the tab does not remove a member.
- `memberId` is generated by the browser, so counts are not tamper-proof.
- One process only: WebSocket subscribers live in this process, so running
  several workers/replicas would split the broadcasts.
